{% comment %} A Django comment, not an HTML one, so none of this is served. An error page is the last thing that should be describing the shape of the system to whoever just triggered it. Standalone on purpose, and the only page in this system that does not extend base.html. Django renders handler500 with an empty context - no context processors run - so SITE_NAME, the signed-in user and everything else the shared layout reads would be blank here. Worse, if the error being reported is the database being unreachable, a layout that touches the database would fail while rendering the page meant to report the failure, and the visitor would get Django's bare "A server error occurred" instead. So: no template inheritance, no stylesheet request, no script. The styles are inline and the palette is copied from app.css rather than imported, which is duplication accepted deliberately in exchange for a page that cannot fail for the same reason the site just did. {% endcomment %}
